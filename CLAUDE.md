# Minecraft Mod Project (NeoForge 1.21.1)

## Build and Test Commands
- Compile and check for errors: `./gradlew compileJava`
- Build final jar: `./gradlew build`
- Run client test: `./gradlew runClient`

## Code Style & Rules
- Use NeoForge 1.21.1 modern architecture.
- Always use `DeferredRegister` and `DeferredHolder` for registering content.
- Do not mix client-only code into common classes.

## Project layout (CC: Bare Metal)
- Mod id `ccbaremetal`, package `dev.ccbaremetal`, main class `BareMetal`; guest C/C++ API `<baremetal.hpp>`/`<baremetal.h>`, library `libbaremetal`, WASM import module `ccbaremetal`.
- `src/main/java/dev/ccbaremetal/kernel` - the WASM machine (VFS, processes, WASI, `ccbaremetal` syscalls, TTY, framebuffer, CC peripheral bridge, CraftOS/Lua). No Minecraft code except `Machine.Host`.
- `userland/` - C++ sources of the guest OS (sh, coreutils, textutils (sed awk diff tar ...), ccutils (rednet gps monitor speaker lp disk inv ...), edit, pkg, periph, init, the `cc`/`c++` compiler driver) and libbaremetal (`include/baremetal.hpp` C++ API incl. typed CC: Tweaked peripheral wrappers and Lua-compatible rednet in `lib/peripherals.cpp`, `include/baremetal.h` raw syscalls). Multi-call binaries: `/bin/<name>` are `#!@/bin/<binary>` aliases generated by the Makefile. `make -C userland` (needs wasi-sdk in `tools/`) writes binaries into `src/main/rootfs`. Userland is built with `-fno-exceptions`.
- In-game toolchain: clang 22 (YoWASP, one WASI module) + wasi-sdk sysroot with libc++ (exceptions on). `userland/build-toolchain.sh` assembles `build/toolchain`; Gradle `precompileToolchain` (src/jittool) translates clang to JVM bytecode at build time (needs 4 GB heap, ~4 min) and writes a slim `llvm.wasm` (compiled function bodies stubbed: the full module costs ~2 GB of heap in Chicory) - the bytecode is bundled as `ccbaremetal/jit/`, the toolchain as `ccbaremetal/toolchain.zip`, unpacked at runtime into `<gamedir>/ccbaremetal/toolchain` and mounted read-only at /usr/lib/llvm and /usr/lib/wasi.
- POSIX compat for ported C programs lives in libbaremetal (`userland/lib/compat.cpp`, `lib/posix.cpp` + header wrappers in `userland/include` using `#include_next`: termios.h spawn.h sys/wait.h sys/ioctl.h sys/soundcard.h sys/resource.h signal.h sched.h pthread.h stdio.h stdlib.h unistd.h): termios, ioctl (TIOCGWINSZ, else the kernel's `fd_ioctl`), waitpid, posix_spawn, system, popen, pipe/dup/dup2 (real syscalls; wasi-libc only stubs them), getpid/kill/setsid/process groups, exec* (spawn+wait+exit), mkstemp & co, tmpfile, sigaction/sigprocmask (dispositions kept; SIG_IGN on SIGINT/SIGTERM sets CC_PROC_CATCH), statvfs (from /proc/mounts), getrlimit, ttyname, getpass, sched/pthread_sigmask stubs. wasi-libc hides many definitions behind `__wasilibc_unmodified_upstream` (struct sigaction, rlimit, L_tmpnam): the wrappers define them as musl does. Linked with `--wrap=statvfs,fstatvfs,sysconf` (besides stat/chmod/access) where libc defines the same symbol in a member we cannot avoid; `sysconf(_SC_NPROCESSORS_*)` = `cpu_count` syscall (min(cores, threads_per_process)). The in-game `cc` defines `_WASI_EMULATED_SIGNAL/PROCESS_CLOCKS/MMAN/GETPID` and links the emulation libs after libbaremetal. No fork (ENOSYS).
- Threads: `cc -pthread` (or `-lSDL2`) targets `wasm32-wasip1-threads` (`-Wl,--import-memory,--export-memory,--max-memory=4294967296`, libbaremetal/crt_cwd from `/usr/lib/wasm32-wasip1-threads`; the toolchain carries that sysroot plus wasi-sdk's compiler-rt for it). Kernel (`proc/WasmProcess`): an imported memory is created per process (shared if declared shared), a module's own shared memory is made once; `wasi::thread-spawn` instantiates the module again on it and runs `wasi_thread_start(tid, arg)` on a new Java thread (`Process.startThread`, `CURRENT` set); proc_exit/trap in a thread kills the process; main's end kills the others (`cleanup`); pending results are per thread; limit `threads_per_process` (config, default 8).
- Sound (`kernel/dev/drivers/SpeakerDriver`): every open `/dev/dspN` is a stream with a 1 s queue (writes block / EAGAIN); one shared "ccbaremetal-audio" thread mixes a speaker's streams every 20 ms and feeds `playAudio` via `Peripherals.callKernel` (works over wired networks) keeping CC's players 0.5-0.75 s ahead; if the speaker ran dry while streaming it calls `stop()` first (CC's client never drops lag otherwise) - only when `Machine.Host.canStopSpeakers()` (ComputerCore: players online and all have CC's `speaker_stop` channel; GameTest mock players don't). Close drains (OSS), a killed process's stream is reset (+stop if alone). CC queues one `speaker_audio_empty` per chunk it takes: the driver counts its chunks (`owedEvents`, reset on stop) and consumes that many in `onEvent` (and pumps), so programs never see the driver's own events. OSS ioctls via `OpenFile.ioctl` / syscall `fd_ioctl`: SETFMT (S8/U8/S16_LE), CHANNELS/STEREO, SPEED 4000-96000 (converted + linearly resampled per stream), GETODELAY, GETOSPACE, RESET, SYNC. `/sys/class/sound/dspN/streams`.
- True colour: `Framebuffer` bpp 16 (RGB565 LE) and 32 (XRGB8888: B,G,R,0) besides 1/2/4/8; colours are 0xRRGGBB there; blit/read data has `bytesPerPixel()` bytes per pixel (stride in pixels); `/dev/fbN` maps raw pixel bytes (`readRaw`/`writeRaw`); network packs 16 bpp as stored, 32 bpp as 3 bytes RGB (`unpackRgb` on the client, `ScreenImage` keeps an int RGB array).
- SDL2 (zlib) is part of the system: `userland/sdl/build.sh` fetches SDL release-2.32.10 (fixed commit), patches the bootstrap list and dynapi (wasi: static), builds it for wasm32-wasip1-threads with `sdl/SDL_config.h` and our video driver `sdl/SDL_ccbmvideo.c` (window = screen at 32 bpp or `SDL_CCBAREMETAL_FB=fbN`, cc_gfx_blit of dirty rects, keys event0 via SDL's linux scancode table, mouse event1, text from the raw tty, Ctrl+C = SDL_QUIT); audio is SDL's OSS driver on /dev/dsp. Installed: /usr/include/SDL2, /usr/lib/wasm32-wasip1-threads/libSDL2.a, /usr/bin/sdl2-config; `man sdl`.
- The TTY encodes xterm mouse (1000/1002/1003 any-motion/1006 SGR), modifier keys (ESC[1;2A ...), DECCKM (ESC[?1h → ESC O A) and OSC 52 clipboard (sent to viewers as `Payloads.Clipboard`); `edit` relies on mouse, keys and OSC 52. Output side has DECSTBM scroll regions, IL/DL/ICH/DCH/ECH and answers ESC[6n/5n/c (replies go into the input queue outside the terminal lock). Raw-mode termios: `CC_TTY_ICRNL` (Enter as \n) and `CC_TTY_TIMED` (VMIN/VTIME packed into the mode word). Plain mouse motion is only sent by the GUI while `Machine.wantsMouseMotion()` (on cell change, ≤20/s).
- Chicory runs only the current WebAssembly exception handling (try_table/exnref): compile C++ with `-fwasm-exceptions -mllvm -wasm-use-legacy-eh=false`.
- Foreign WASI programs (clang, lld) do not know the shell's cwd (only our crt_cwd.o reads $PWD), so the `cc` driver makes paths absolute; binutils go through it too.
- Addon compatibility is generic (no per-mod code): peripherals via CC's method generator, objects returned by methods become handles for WASM programs (`kernel/proc/ObjectTable`, `obj_call`), and addon global APIs (`registerAPIFactory`) are created per machine (`kernel/periph/AddonApis`) - Lua globals, `cc::api` in C++.
- HTTP: CC's own `HTTPAPI` (requests, websockets, checkURL; CC's config, address rules, limits) runs on our machine through `kernel/periph/HttpEnvironment` (an `IAPIEnvironment`: events, timers for the calling process, user agent), registered in `AddonApis` as "http" when `CoreConfig.httpEnabled` (Lua global, `cc::api` in C++). Bodies reach WASM byte-exact through the `obj_call_raw` syscall (`Object::callBytes`); `cc::http` in libbaremetal, `curl`/`wget` in ccutils, `pkg install URL`.
- Device model (Linux-like, `kernel/dev`): `DeviceTree` = peripheral bus + drivers + devices by class; `/dev` (`DevBackend`: fixed nodes + tree nodes + /dev/periph) and `/sys` (`SysBackend`: /sys/class/CLASS/NAME/ATTR, /sys/bus/peripheral/devices/NAME/{type,driver,devices}) only show the tree. A `Device` declares its class, name prefix (numbered: lowest free), optional node, attributes (read/write, anyone or root) and `onEvent` (true = consumed); every device also gets `uevent` (DEVNAME) and `device` (peripheral). Drivers (`Driver`, one file each in `kernel/dev/drivers`, first match wins, registered in the Machine constructor): PixelMonitor (FramebufferProvider → `GraphicsDevice` fbN + `TouchscreenDevice`), Monitor (tty monitorN + touchscreen), Speaker (sound dspN), Printer (printer lpN), Modem (net wlanN/ethN). Built-ins in `ComputerDevices`: fb0, input event0/event1/mice (`kernel/io/InputHub`), redstone sides. The bus follows the "peripheral"/"peripheral_detach" events (sides and wired networks; `Peripherals.typesDirect`); removal revokes open device files (ENODEV). Unknown peripherals: only `/dev/periph` (`PeriphFiles`, the generic method/event files). Rule: migrate fully, no old path beside a new one; every device low-level (/dev, /sys, syscall/C++) and high-level (sh command on top: `lsdev`, `ip`, `fbset`, `evtest`...).
- CraftOS/Lua on our machine: `term.write`/`blit` store one CC byte per cell (bytes >= 0x80 as U+F780..F7FF, `kernel/tty/RawText`), compacted to UTF-8 characters only in what is shown (`Terminal.snapshot`/history, mouse via `cellAt`); typed non-Latin-1 chars reach Lua as "paste"; `LuaProcess.utf8Read` patches bios read() to move by UTF-8 characters (all-or-nothing; `LuaProcessTest` checks it applies).
- Unicode for CC: Tweaked's own computers (`dev.ccbaremetal.unicode`, mixins in `ccbaremetal.mixins.json`, all optional/require=0): CC keeps bytes (one per cell), only drawing compacts UTF-8 per segment (`Utf8Layout`), typed/pasted non-CC chars become UTF-8 "paste" events. Never fork CC. `BAREMETAL_RENDER_PREVIEW=file.png ./gradlew runClient` (e.g. inside `kwin_wayland --virtual --xwayland`) renders a sample through CC's renderer and quits.
- `src/main/rootfs` is committed and zipped into the jar as `ccbaremetal/system.zip` by Gradle (`zipRootfs`).
- Computer server side is `computer/ComputerCore` (machine, viewers, screen sync, input, power), held by `WasmComputerBlockEntity` (block: side peripherals, redstone) and `pocket/PocketCore` (pocket computer item). Pocket: runs while ticked in an inventory (`PocketCores`, stops after 40 ticks unticked), 4 module slots stored in the item component `pocket_upgrades`; each slot gets its own `IPocketAccess` view so CC's single-upgrade pocket API works per slot (peripherals `back`, `slot2..4`); upgrades are found generically in CC's `IPocketUpgrade.REGISTRY` (`pocket/PocketUpgrades`). `ComputerScreen` is a plain `Screen` + `MenuAccess` (not a container screen), so JEI/EMI/Inventory Profiles Next overlays never cover the terminal; the module slots are a separate container screen `client/PocketModulesScreen` drawn over it (switching keeps the menu open: only the computer screen's `removed()` is skipped).
- Turtle (`turtle/`): `WasmTurtle` is the state + CC's `ITurtleAccess` + `ComputerCore.Owner`; it outlives `WasmTurtleBlockEntity` (moving = `teleportTo` places a new block, the new BE `adopt`s the turtle, `ComputerCore.setOwner`, the old block is removed without stopping the machine or spilling). Commands queue to the server tick (8 ticks per move/turn); `TurtleApi` (peripheral "turtle", a `kernel/periph/HostApi` so CraftOS gets the global `turtle` and Lua's peripheral API hides it) blocks the calling guest thread. CC's tool upgrades throw in `TurtlePlayer.get` ("not a brain") on non-CC turtles, so `TurtleTools` digs/attacks with the upgrade's item via a NeoForge FakePlayer. Upgrade models come from CC's internal `client.turtle.TurtleUpgradeModellers` (`WasmTurtleRenderer`). Shell: `turtle` (ccutils).
- The computer window (`client/ComputerScreen`) copies CC's advanced computer GUI: CC's border + sidebar sprites recoloured to amethyst and CC's buttons plus our reboot/zoom icons (`scripts/gen_gui_textures.py` → `textures/gui/sprites`). The frame and sidebar are drawn at the GUI scale (`art`) and always fill the window; the zoom only sets the font pixel size (integer window pixels), and the terminal gets the columns/rows that fit; graphics use the largest integer scale that fits. `BAREMETAL_RENDER_PREVIEW` also writes `-gui.png`/`-gui-off.png` of this window.
- Block textures are generated from CC: Tweaked's own advanced computer/monitor textures (read from the CC jar in the Gradle cache), gold body recoloured to amethyst per pixel by `scripts/cc_textures.py` (grey frame and screen untouched): `scripts/gen_computer_textures.py` (WASM computer, CC's computer_blink cursor) and `scripts/gen_monitor_textures.py` (pixel monitor: picks CC's monitor_advanced_N whose frame matches each neighbour mask, writes models + blockstate; block state left/right/up/down set by MonitorGroups).
- Users and permissions (Linux semantics): `Stat` has mode/uid/gid; `kernel/proc/Cred` per process (`Cred.current()`: the calling process, `Cred.as` for the kernel acting for a user, root otherwise); `Vfs` checks search/read/write/sticky and sets owners on create (umask, setgid dirs). The computer's disk keeps owners in `<id>.meta` next to its folder (`HostBackend`, only non-default entries); system image root-owned, `bin/su|sudo|passwd` setuid (`ImageBackend.SETUID`). Exec needs x; setuid applies to WASM/alias, not `#!` scripts. libbaremetal `lib/users.cpp`: getuid/setresuid/getpwnam/getspnam/chown/umask and `-Wl,--wrap` of stat/chmod/access (Makefile and the cc driver). `userutils`: setup (first boot: init runs /sbin/setup while /etc/firstboot exists; tests and GameTests skip it with -Dccbaremetal.unattendedSetup=true, which keeps the old password-less autologin "user"), login (/etc/autologin: "NAME" only while the password is empty, "NAME always" from `sudo autologin NAME`, root-owned, once per boot via /run/autologin-done; exit 200 = show prompt again), su, sudo (/etc/sudoers + sudoers.d parsed in userutils: aliases, runas, NOPASSWD, negation, last match wins; visudo; /run/sudo timestamps; logs to /var/log/auth.log), passwd, useradd...
- sh: compound commands in a pipeline or with `&` run as a child `sh -c` with the parent's state (stateScript: variables, functions from their saved source text, aliases, positional); tokens carry source offsets for that. cat copies with read()/write() so endless streams show at once.
- Screen lock: `Machine.lockScreen` shows a separate `lockTerminal`/`lockTty` (`shownTerminal()`/`shownDisplay()` are what viewers get, ComputerCore resends on switch) running `/bin/lock --screen UID` as root; all GUI input goes only there (not to /dev/input or programs); the prompt calls `screen_unlock` (only its ctty may), is respawned if it dies; auto-lock in `Machine.tick` after `screen_autolock` seconds without input (login sets it from /etc/lock.conf LOCK_AFTER, `lock -t`). screen_* syscalls only from the console ctty. `sys_shutdown` only for root or the console ctty (not ssh users); `shutdown +M/HH:MM/-c/--show` (coreutils) schedules a `shutdown --scheduled WHEN ACTION MSG` background process that warns via `tty_broadcast` (console, lock prompt, every pty).
- Devices that go away: `OpenFile.revoke(errno)`; PeriphFiles revokes on peripheral_detach (ENODEV), CcMountBackend on unmount (EIO).
- Keyboard (`computer/KeyboardItem` = BlockItem of `KeyboardBlock`/`KeyboardBlockEntity`, linked via COMPUTER_ID, placeable only once linked; computer/turtle blocks skip their GUI for it in `useItemOn`): `KeyboardMenu.open(player, core, valid)` (server: `Machine.attachKeyboard` → `kernel/dev/KeyboardDevice` input eventN with keys + relative mouse; valid: `holding` = in hand ≤64 blocks of the computer, or the block's predicate = block still there, player ≤8 blocks, computer ≤64 from the block; `removed` detaches) and client `KeyboardScreen` (no window/blur, cursor disabled, the head turns with the mouse like MouseHandler.turnPlayer, every key incl. Esc sent as Payloads.Input; Shift+Esc closes; mouse deltas ≤20/s as mouse_relative/button/wheel). `Machine.keyboardInput`: keys through the normal input path + device; mouse to the device and as CC events to the foreground. `ComputerCore.find(id, level)`.
- Files dropped on the window: `computer/FileUpload` (UploadStart/UploadData/UploadReply payloads), written as the foreground process's user into its cwd; WebAssembly modules and #! scripts get 0755.
- Pseudo-terminals: `tty/Pty` + `Tty` in pty mode; `Process.ctty` (inherited, `SPAWN_CTTY` takes stdin's tty), per-tty foreground group, /dev/tty = the caller's ctty. `event_wait_fds` waits for fds and events together (`cc::waitAny`). `kernel/sys/Crypto`: X25519/Ed25519/ChaCha20-Poly1305/SHA-256 via the JDK. Network: `kernel/net/Net` is a small TCP over modems ("ccnet"): sockets are fds (`Net.Listener`/`Net.Conn` OpenFiles; syscalls net_listen/accept/connect/shutdown/info; `cc::net` in libbaremetal `lib/net.cpp`); a computer listens on `Net.addressChannel(hostname)` (FNV-1a, 100..60099; `Machine.hostname()` = /etc/hostname, label, computer-N), ports inside packets, go-back-N retransmission, window, fin/rst; `hid` (random per boot) detects two computers with one name (EADDRINUSE on the connection). The stack sends through net-class devices (`NetDevice`: `ModemDriver`'s interface, `Loopback` "lo"; attributes type/operstate/address/mtu/statistics); a modem interface takes ccnet packets for this computer in `onEvent` (consumed, not delivered to programs) and they are handled on the single shared "ccbaremetal-net" thread - never transmit inside queueEvent (CC delivers synchronously, would recurse); `Machine.tick` drives retransmits/channel re-open (closeAll). `Peripherals.callDirect` calls modem methods without a guest process. Sockets list: /proc/net/ccnet (`cc::net::status`). `nc`/`ss`/`netstat`/`ip`/`lsdev` in ccutils. `ssh`/`sshd` (`userland/src/ssh.cpp`, protocol ccbaremetal-ssh-2): one cc::net connection per session, length-prefixed frames (plain JSON hellos, then ChaCha20-Poly1305 with counter nonces); sshd -p, /etc/ssh/sshd_config as OpenSSH's, /var/log/auth.log; publickey auth via ssh-keygen/authorized_keys; client ~/.ssh/config. Sessions with a command run without a pty (pipes: in/out/err/eof messages, sshd waits on the listener, sockets and session fds with cc::waitAny); scp speaks the classic SCP protocol to a remote `scp -t`/`-f` over `ssh -T`; host key /etc/ssh, ~/.ssh/known_hosts by name. Syscalls that return a pid or count report errors as -errno (the `wait` syscall once returned +ECHILD, which made `while (wait(..) > 0)` spin).
- pkg (`userland/src/pkg.cpp`): .ccpkg = "CCPKG1\n" + manifest JSON line + D/F records + "E"; installs into /usr/local, records /var/lib/pkg/NAME.{json,list}; the json keeps "origin" (repo, file path or URL) for `pkg update`/`upgrade` (compareVersions by parts; upgrade removes dropped files; downloads cached in /var/cache/pkg). Install = pass 1 checks the package is whole and fits (statvfs), pass 2 writes every file as PATH.pkgnew (checked fwrite/fclose), then renames all; any failure deletes the .pkgnew files and leaves the installed version. Repos in /etc/pkg/repos: dirs or URLs of a dir with index.json (`pkg index DIR`: name/version/.../file/size/sha256); `pkg update` fetches indexes into /var/cache/pkg/index; network packages are downloaded on install and checked (size, SHA-256); `pkg repo list|add|remove`. System dirs are created on the root disk itself (`Machine.onDisk`: /usr only "exists" through the image mounts, /usr/local used to be missing). Ports are separate projects shipping .ccpkg files; never mentioned in the mod.
- Docs in two languages kept in sync: `README.md` + `docs/en/` (English), `README.ru.md` + `docs/ru/` (Russian), same file names; images in `docs/images`.
- Fonts: `src/main/resources/ccbaremetal/font/glyphs.txt` (hand-drawn), `compose.txt` is generated by `scripts/gen_font_compose.py`.
- Logo: `scripts/gen_logo.py` (40x40 pixel art drawn from scratch, MPL like the code) → `docs/images/logo.png` (400x400, README and mod sites) and `src/main/resources/ccbaremetal_logo.png` (`logoFile` in neoforge.mods.toml).

## Tests
Local only: `src/test/`, `src/main/java/dev/ccbaremetal/gametest/` and the `structure/` template are in .gitignore and excluded from the jar; never mention tests in README/docs.
- Kernel tests (no world): `./gradlew test` (MachineTest compiles C++ in a machine; toolchain/JIT caches in the system temp dir)
- In-world GameTests: `./gradlew runGameTestServer`
